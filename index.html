1. Why salting matters

The same password hashed twice. Without a salt the results are identical, so one precomputed rainbow table cracks every user. With a random salt every hash is unique.

2. Avalanche effect

Change one character and about half of the hash bits flip. Good hashes leak nothing about how close two inputs are.

Hashing vs encryption vs encoding
  • Hashing is one-way. You cannot recover the input, you can only check a guess against the hash.
  • Encryption is two-way with a key. Passwords should never be stored encrypted.
  • Encoding (Base64, URL encoding) only changes the format and provides no secrecy.
How entropy is calculated

entropy = length × log2(pool size)

A 10-character password using all 94 printable ASCII characters has 10 × 6.55 = 65.5 bits. Each extra bit doubles the number of guesses needed. This tool then lowers the figure for predictable parts such as 1234, qwerty, repeated characters, years and dictionary words.

Salt, pepper and work factor
  • A salt is a random, non-secret value stored with each hash. It defeats rainbow tables and hides duplicate passwords.
  • A pepper is a secret value kept outside the database and mixed into every hash.
  • A work factor (iterations, cost) makes each hash slower, which limits how many guesses an attacker can make.
What should a real website use?

Argon2id (preferred), bcrypt or scrypt, with a per-user salt, hashed on the server. Browsers do not offer Argon2 or bcrypt natively, which is why this demo uses PBKDF2, the strongest password hash built into Web Crypto.

Limitations of this tool
  • Entropy is an estimate that treats characters as random, so passphrases of ordinary words are over-estimated.
  • The built-in wordlist is small. Real attackers use lists with billions of entries.
  • No check against personal information such as names or birthdays.
  • Crack-time figures assume fixed attacker speeds that change with hardware.
