Where is this hash stored?

Nowhere. These samples are written into the page itself, and everything you paste is checked in your browser then forgotten. A real website would keep hashes in its database on a server (the backend). This tool has no backend because it does not need one.

Entropy: "how unpredictable is it?"

Entropy is a score, in bits, for how hard something is to guess. Every extra bit doubles the guesses a hacker needs. 28 bits is crackable in seconds, 60 bits is hard, 80+ bits is practically safe.

entropy = length × log2(pool) where the pool is how many different characters you could have used (26 for lowercase only, 94 for all keyboard characters). We then lower it for predictable bits like 1234.

Hash: a one-way scrambler

A hash turns any text into a fixed-length string of letters and numbers. The same input always gives the same output, but you can never go backward from the output.

Hashing, encryption and encoding
  • Hashing: one-way. Used to store passwords.
  • Encryption: two-way with a secret key. Not for passwords.
  • Encoding (like Base64): just a format change, no secrecy at all.
Salt, pepper and work factor
  • Salt: random extra text mixed in per user. Stops one stolen table cracking everybody.
  • Pepper: a secret extra ingredient kept outside the database.
  • Work factor: how many rounds the hash repeats. More rounds means slower guessing.
The methods used in PassGuard
  • MD5, SHA-1: old and broken. Shown only for comparison.
  • SHA-256, 384, 512: strong fingerprints, but too fast for passwords.
  • PBKDF2: repeats SHA-256 hundreds of thousands of times with a salt. Suitable for passwords.
  • Web Crypto API: the secure toolkit built into your browser that does the maths.
  • Rejection sampling and shuffle: tricks that make the generator perfectly fair and unbiased.
  • Brute force: trying every possibility. Crack times assume this.
Is there a backend or database?

No. PassGuard is a "static" site: all the work happens in your browser and nothing is stored. Real websites need a backend to keep hashes in a database. They should use Argon2id, bcrypt or scrypt, which browsers do not offer, so this demo uses PBKDF2.

Limits of this tool
  • Entropy is an estimate.
  • The common-password list is small. Real attackers have billions.
  • Names and birthdays are not checked.
  • Crack times depend on the attacker's hardware.
